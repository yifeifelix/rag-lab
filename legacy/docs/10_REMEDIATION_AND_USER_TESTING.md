## 评测与校准

新版挑战资料位于 `data/learning_v2/`：81 篇文档、82 道开发题、83 道测试题。虚构政策包含同主题不同地区、操作与归档版本的干扰；另含原有 CPython docstrings。题目组和标准化问题哈希不跨 split，manifest 固定数据哈希；逐题标注必要文档及支持片段。未标注关键词的题目，其关键词覆盖率为 null 并从均值中排除，不用 1.0 填补。

**测试题仍由同一代理编写，不能称为独立盲测。** 扩容和分组隔离解决程序复用问题，不能追溯性地创造作者独立性。用户自行编题、人工审核与冻结后的测试才是下一阶段外部效果依据。

校准只访问 dev。按问题组交叉拟合预测“所有必要检索证据是否出现”，用错误接受成本 4、错误拒绝成本 1 选择阈值，再拟合最终映射。它不估计答案事实正确率。报告保留 OOF Brier、覆盖率、错误接受、错误拒绝及各阈值取舍。

改代码、语料或影响评分的配置后，旧校准不再适用。切换请求检索模式、重排开关、top-k 或 domain filter 时，不沿用另一条件的校准。最终 test 入口验证冻结记录，不能一边选参数一边更新最终成绩。

## 增量与运行边界

Qdrant REST 路径采用固定版本 encoder、不可变 chunk/vector ID、当前快照 ID 过滤和提交后清理；旧快照退回已有的本地向量以完成在途请求。使用真实查询、upsert、scroll、delete 端点；模拟 REST 契约覆盖更新、删除、重启、域过滤和向量复用。[Qdrant 查询接口](https://api.qdrant.tech/api-reference/search/query-points)

此实现仍使用原子 JSONL 保存语料；每次保存需序列化语料和发布元数据。Qdrant 快照 ID 过滤的请求大小随 chunk 数量增加，不是大规模生产方案。模型切换使用新的集合；历史模型集合与索引空间的保留/清理由 owner 管理，删除当前活动模型的数据不等于跨历史模型的合规擦除。

真实 cross-encoder 通过 `SentenceTransformers.CrossEncoder` 执行 query/passage 联合推理，默认 BGE；没有依赖或缓存时明确失败。MiniLM / BGE 下载后记录不可变模型版本并做实际推理检查，不用特征重排静默冒充神经模型。[官方 CrossEncoder 文档](https://www.sbert.net/docs/package_reference/cross_encoder/model.html)

用户测试为一个共享工作区，tester 只读资料、问答与反馈；owner 可编辑与运行实验。没有独立租户或文档 ACL。反馈和运行报告默认写入 `reports/private/`，不推送 GitHub。
