# 求职与 Freelance 展示口径

## 可以使用的当前项目描述

> 构建本地 RAG 学习与评估工作台，实现四类分块、BM25/SVD 向量混合检索、RRF、特征重排、文档生命周期和可复现实验。通过回归测试修复缓存跨配置错答与原始 PII 缓存问题，使用真实 CPython 文档建立来源可追溯的案例，并导出逐题证据供人工评审。

性能实验需要补充限定：单进程、10,000 协程请求、构造流量和模拟生成等待。它不是经过生产验收的真实模型万并发服务。

## 面试应能解释的内容

1. 为什么把 TF-IDF + SVD 当作离线基线，它与预训练 embedding 的能力差别是什么？
2. 为什么 BM25 可能在技术编号场景优于复杂管线？RRF、重排增加的延迟换来了什么？
3. 为什么高 Recall 和词项覆盖满分仍可能答错？如何设计声明级证据和独立人工评估？
4. 为什么缓存淘汰时不能保留可变列表的位置索引？如何通过跨 scope 回归测试复现并修复？
5. 为什么检索前脱敏仍可能在 response cache 留下原始查询？如何检查所有持久化路径？
6. 为什么并发用户数、在途请求、请求数量和 RPS 不能混用？
7. 如何证明文档更新/删除后没有继续复用旧答案？
8. 外部模型失败时如何显式展示降级，而不是悄悄以本地回答充当成功？

讲述你实际执行过的修改、测试和实验。不要把合成资料中的企业客户、SLA、合规制度、成本或故障故事当作个人工作经历。

## Freelance 可以提供的演示范围

- 公开文档/获准使用资料的单用户知识助手 PoC。
- 检索质量诊断：问题集、证据、失败分类、基线对比和改进建议。
- 边界清楚的小型 MVP 演示：导入、问答、来源、更新、删除、重启和交接说明。

客户正式验收前需约定：资料来源和许可、质量标准、可拒答范围、并发/延迟、模型费用、部署环境、权限和维护责任。

私有多用户数据需要真正的身份和文档 ACL。owner token 不是租户隔离。当前项目没有已验证的企业合规、生产 SLA 或大规模容量承诺。

## 下一阶段最有价值的成果

选择一个与目标岗位或客户贴近的领域，用真实资料和独立评审的问题集完成实验。提交可解释的质量/成本/延迟取舍及失败样例。报价应按需求、交付风险和维护责任制定，原始文档中的套餐价格不作为市场依据。
