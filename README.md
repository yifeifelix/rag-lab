# RAG Lab

A hands-on course for learning **Retrieval-Augmented Generation** from first principles.
Eleven lessons, each with a short explanation, runnable code, auto-checked exercises and links to
the best community notebooks for going deeper.

| You get | Where |
|---|---|
| Interactive lessons + exercises (JupyterLab) | `http://<this-mac>:8888` |
| Read-only course website | `http://<this-mac>:8000` |
| Lesson sources | `course/` (your editable copies live in `workspace/`) |
| Small, readable RAG library used by the lessons | `src/raglab/` |
| Corpora and labelled questions | `data/python_docs/`, `data/policies/` |
| Community repos for deeper study (local only) | `references/` |

## Curriculum

| # | Lesson | Exercise |
|---|---|---|
| 0 | What is RAG? A full system in 10 lines | - |
| 1 | Documents and chunking | implement a fixed-size chunker |
| 2 | Embeddings | implement cosine similarity |
| 3 | Vector search | implement top-k |
| 4 | Keyword search with BM25 | implement IDF and the BM25 term score |
| 5 | Hybrid search with RRF | implement Reciprocal Rank Fusion |
| 6 | Re-ranking with a cross-encoder | tune the candidate pool |
| 7 | Generation from sources | write a grounded, citing, refusing prompt |
| 8 | Evaluation | implement Recall@k and MRR, build a leaderboard |
| 9 | Query transformations (Multi-Query, HyDE) | build query decomposition |
| 10 | Self-correcting and agentic RAG | evaluate CRAG vs. plain RAG |

Lessons 0-6 and 8 (retrieval parts) run fully offline: the embedding model
(`BAAI/bge-small-en-v1.5`) and re-ranker (`cross-encoder/ms-marco-MiniLM-L-6-v2`) are baked into
the image. Lessons 7-10 need a chat model through any OpenAI-compatible endpoint.

## Run it (OrbStack or Docker Desktop)

```bash
scripts/lab up        # build + start JupyterLab (8888) and the website (8000)
scripts/lab book      # execute all lessons and (re)build the website
scripts/lab refs      # clone / update the community repos into references/
```

`scripts/lab up` prints the JupyterLab URL including its access token (also: `scripts/lab token`).
Other commands: `down`, `status`, `logs`, `test`, `reset NN` (fresh copy of lesson NN).

### Connect a chat model

Edit `.env` (created from `.env.example` on first run):

```bash
LLM_BASE_URL=http://host.docker.internal:8317/v1   # e.g. cliproxyapi running in OrbStack
LLM_API_KEY=...                                     # a key from that proxy's config
LLM_MODEL=...                                       # a model id it serves
```

Then `scripts/lab up` again. In a notebook, `from raglab.llm import list_models; list_models()`
shows which models the endpoint offers.

### LAN access

By default both services listen on all interfaces so other computers on your network can open
`http://<this-mac-ip>:8888` (with the token) and `http://<this-mac-ip>:8000`. JupyterLab runs code,
so share its token only with people you trust, and never expose these ports to the internet.
Set `LAB_BIND_HOST=127.0.0.1` in `.env` to restrict both to this machine.

## Community repositories

open-source licence, so their content is never copied into this project):

- [mrdbourke/simple-local-rag](https://github.com/mrdbourke/simple-local-rag) - a full local pipeline in one notebook
- [KalyanKS-NLP/rag-zero-to-hero-guide](https://github.com/KalyanKS-NLP/rag-zero-to-hero-guide)
- [datawhalechina/all-in-rag](https://github.com/datawhalechina/all-in-rag) (Chinese)

## Data and licences

- `data/python_docs/` - docstrings of 45 Python 3.12 standard-library modules
  (Python Software Foundation License), regenerated by `scripts/build_corpus.py`.
  `qa.jsonl` holds 42 questions; each stores the exact supporting sentence, verified by the tests.
- `data/policies/` - a small fictional policy set (MIT) with superseded versions, look-alike
  regions and unanswerable questions, used to teach generation traps.
- Code: MIT (see `LICENSE`).
