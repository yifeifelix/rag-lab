# 4 · Keyword search with BM25

**Time:** 45 minutes · **You will:** implement the two halves of the BM25 formula and see where it beats embeddings.

## Why bring back "old" keyword search?

In lesson 2 you saw embeddings stumble on exact identifiers (`shutil.copytree`), error codes and
rare names. Keyword search is the opposite: no understanding of synonyms, but it never confuses
`copytree` with `copy`. **BM25** (1994!) is still the default keyword scorer in Elasticsearch,
OpenSearch and Lucene - and a strong baseline that fancy systems often fail to beat.

## Step 2 · Term frequency, with a ceiling

A chunk mentioning *queue* 10 times is more about queues than one mentioning it once - but not
10× more. BM25 makes term frequency **saturate**, controlled by `k1` (usually 1.2-2.0):

```{code-cell} ipython3
import numpy as np, matplotlib.pyplot as plt
tf = np.arange(0, 21)
for k1 in (0.5, 1.5, 3.0):
    plt.plot(tf, tf * (k1 + 1) / (tf + k1), label=f"k1={k1}")
plt.plot(tf, tf / 4, "--", label="raw tf (scaled)", alpha=.5)
plt.xlabel("times the word appears in the chunk"); plt.ylabel("contribution"); plt.legend(); plt.show()
```

It also adjusts for **length**: a match in a short chunk is stronger evidence than the same match
in a very long one. `b` (usually 0.75) controls how much: `1 - b + b * doc_len / avg_len`.

## Step 3 · Inverse document frequency (IDF)

Words that appear everywhere (*return*, *value*) tell us little; rare words (*rmtree*) are gold:

$$\text{idf}(t) = \ln\left(1 + \frac{N - df(t) + 0.5}{df(t) + 0.5}\right)$$

where `N` = number of chunks and `df(t)` = how many chunks contain term `t`.

## BM25 vs. vectors, head to head

`raglab.retrieval.BM25Retriever` puts your two formulas together (read it in `src/raglab/retrieval.py`).

```{code-cell} ipython3
from raglab import load_documents, chunk_documents
from raglab.retrieval import BM25Retriever, VectorRetriever

docs = load_documents("python_docs")
chunks = chunk_documents(docs, "recursive", max_chars=800)
bm25, vec = BM25Retriever(chunks), VectorRetriever(chunks)

queries = ["shutil.rmtree", "TimeoutExpired", "heappush",                      # exact names
           "make my program wait a bit", "get rid of a folder and its contents"]  # paraphrases
for q in queries:
    b = bm25.search(q, 1); v = vec.search(q, 1)
    print(f"{q!r:42} BM25 -> {b[0].doc_id if b else '(nothing)':18} vector -> {v[0].doc_id}")
```

Typically: BM25 nails exact names, vectors nail paraphrases. Neither wins everywhere - which is
exactly why lesson 5 combines them.

## Key takeaways

- BM25 = sum over query terms of IDF × saturated, length-normalised term frequency.
- It is fast, explainable ("these words matched") and excellent for exact terms.
- It fails on synonyms and paraphrases.
